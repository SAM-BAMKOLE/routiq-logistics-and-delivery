# Routiq web console

The operator-facing frontend for the Routiq LDMS API. Next.js (App Router,
React 19, Tailwind v4) talking to the API over HTTP only — no database access,
no server-side session, no secrets.

## What's here

| Route | Purpose |
| --- | --- |
| `/login` | Email + password sign-in against `POST /auth/login`. Seeded demo accounts are listed for one-click fill. |
| `/dashboard` | Snapshot: shipment counts, delivered value, drivers on shift, recent shipments. |
| `/shipments` | Shipment list with client-side status filter. |
| `/shipments/[id]` | Detail, status timeline, public-tracking link, and `confirm` / `cancel` actions (sent with `If-Match`). |
| `/drivers` | Driver profiles with status, availability and current vehicle. |
| `/customers` | Customer list; expand a row to lazy-load its saved addresses. |
| `/tracking` | The anonymous `GET /public/tracking/:number?token=…` lookup, prefillable via `?number=&token=`. |
| `/pricing` | Rate cards (base fee, per-km, per-kg, minimum, priority). |

Auth tokens live in `localStorage` (see `src/lib/session.tsx`) and the API
client refreshes them transparently on a 401. This is fine for the demo; a
production deployment would move the refresh token to an httpOnly cookie.

## Stack notes

The UI kit in `src/components/ui/` is intentionally small and hand-written
(clsx + tailwind-merge + class-variance-authority + lucide-react) rather than
generated by the shadcn CLI, which produced broken components against this
Tailwind v4 / React 19 combination. The visual language and CSS variables in
`src/app/globals.css` follow the standard shadcn theme, so dropping in real
shadcn components later is a copy-paste job.

## Running it

The API must be up first (`cd ../api && pnpm start:dev`), then:

```bash
pnpm install
cp .env.example .env.local     # set NEXT_PUBLIC_API_URL if the API isn't on :3000
pnpm dev
```

The dev server picks the first free port — if the API already holds `3000`,
this lands on `3001`. Make sure that exact origin is in the API's
`CORS_ORIGINS` allow-list (the shipped `.env.example` includes both).

```bash
pnpm build      # production build + type check
pnpm start      # serve the built app
```

## Configuration

| Variable | Default | Meaning |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | `http://localhost:3000/api/v1` | API origin including the `/api/v1` prefix. Baked in at build time. |
